# Decisions

Defaults chosen where the brief was silent or where the brief conflicted with the platform. Newest last.

| # | Decision | Why |
|---|---|---|
| 1 | Repo root is `Technomile/` (the project folder), with `backend/`, `frontend/`, `eval/` and `docs/` directly inside. | The brief's `snapfix/` layout is the project root; the hackathon folder is named Technomile. |
| 2 | **Structured outputs (`output_config.format` / `client.messages.parse`) instead of a forced `tool_choice`** for the photo → ticket extraction. The JSON schema is the brief's `create_ticket_draft` schema. | Claude Sonnet 5.5 returns HTTP 400 for forced `tool_choice` (`{"type":"tool"}` / `{"type":"any"}`). Structured outputs give the same guarantee that the response is valid JSON matching the schema. |
| 3 | No `temperature` parameter on any call. Extraction uses `output_config.effort="low"` for speed. | Sonnet 5.5 and Haiku 5.5 reject non-default sampling parameters. `effort` is the supported lever for latency vs depth. |
| 4 | Clustering uses **scikit-learn's `HDBSCAN`** (same algorithm as the `hdbscan` package). | Avoids a native build of `hdbscan` on Windows/Python 3.12; one less dependency. |
| 5 | Tests run on **in-memory SQLite + a deterministic hashing embedder**; the app runs on PostgreSQL 16 + pgvector with bge-small. Models are written to be portable (pgvector columns become JSON on SQLite; similarity falls back to numpy). | `make test` needs no Docker, API key, model download or internet, so tests are fast and run anywhere. |
| 6 | If `LLM_MODE=live` but `ANTHROPIC_API_KEY` is empty, the app **automatically runs in mock mode** (logged once). | The app, tests and demo always start; nothing breaks on stage because of a missing key. |
| 7 | **10 teams, one per trade** (brief said about 8). | Routing becomes a 1:1, explainable mapping (trade → team). |
| 8 | Seeded room numbers are **unique across campus** (ENGR x01–x18, LIB x20–x33, STUC x40–x52). | "I smell gas near room 210" always resolves to exactly one room, even without a QR code. The resolver still handles ambiguity in general. |
| 9 | Added `Location.room_type` (lab, restroom, elevator, ...) and floor-plan rectangle fields (`x, y, w, h`). | Room type drives location criticality for priority (labs, restrooms, elevators are higher); rectangles let us draw floor plans and hotspots in plain SVG. |
| 10 | Added `Ticket.source` (`snapfix` vs `seed`). AI-performance KPIs (photo → ticket latency, time-to-triage) count **only real pipeline tickets**. | We never present synthetic numbers as measured performance. |
| 11 | No HNSW index on embeddings; exact KNN with filters (same building, open, last 72 h). | At campus scale (thousands of tickets) exact search is fast and avoids recall loss from filtered approximate search. Add HNSW past ~100k tickets. |
| 12 | The browser always calls same-origin `/api` and `/media`; **Next.js rewrites proxy them to FastAPI** (`BACKEND_URL`, falling back to `NEXT_PUBLIC_API_URL`). | A phone needs only one HTTPS tunnel (to the frontend) for camera + microphone. `compress: false` keeps SSE unbuffered. |
| 13 | shadcn/ui components are vendored by hand in `frontend/components/ui` (Button, Card, Badge, Input, Tabs, ...). | Same code shadcn's CLI would generate, without an interactive CLI step in the build. |
| 14 | Historical open tickets older than their SLA are resolved during seeding; planted scenarios keep their timing. | A believable queue: most open work is within SLA, with a few deliberate tension points (hazard just overdue, repeat-failure sink about to breach). |
| 15 | Seed resets keep `timing_runs` (baseline vs SnapFix time-to-report measurements). | Those are real volunteer measurements, not demo data. |
| 16 | Hazards force severity 4 and P1. "Wet floor" alone is **not** a hazard keyword (it's a spill); "slippery", "someone fell", "black ice" are. Keyword rules prefer recall; negations ("no smoke") still escalate. | Avoids alert fatigue from every spill while keeping 100% recall on dangerous phrasing. Safety errs on the side of escalation. |
| 17 | The browser downscales photos to 1568 px before upload, after reading EXIF GPS with a small parser and sending it as `lat`/`lng`. The server still validates, strips metadata and re-encodes. | Phone photos are 3–12 MB; uploads over a phone tunnel stay fast without losing the GPS location hint. |
| 18 | "Photo → ticket" = server processing time (analysis + confirm), shown on the result screen; the reporter's total time (page open → submit) is measured separately in the browser and logged as a `snapfix` timing run. | Separates AI/system latency from human think time; the second number feeds the baseline comparison. |
| 19 | The UI keeps the "Analyzing…" skeleton up for at least 0.7 s; that delay is never included in measured latency. | Avoids a jarring flash in mock mode without inflating or faking numbers. Mock mode is always labelled "Offline demo mode". |
| 20 | Trade is always derived from the category (fixed mapping), even if the model returns a different trade. | One source of truth for routing; the model can't send a plumbing issue to Electrical. |
| 21 | Dedupe text similarity is the bge cosine **rescaled** (0.55 → 0, 0.90 → 1) before the 0.55/0.25/0.20 formula. | Measured on bge-small: same issue reworded ≈ 0.82–0.87, related-but-different ≈ 0.75–0.78, unrelated ≈ 0.52–0.63. Raw cosine made unrelated reports in the same room look similar. |
| 22 | **Auto-merge only within the same room.** A score ≥ 0.80 in another room goes to the Haiku check instead. | Identical wording ("water dripping from the ceiling") in two rooms usually means two separate leaks; caught in testing against Postgres. Root-cause grouping across rooms is the clustering feature's job. |
| 23 | Hazard reports merge **deterministically** (same room + same hazard type, or a clear same-room match) without waiting for Haiku. Merging into an existing hazard does not re-alert; a merge that turns a normal ticket into a hazard does. | Keeps the P1 path under 2 s with no LLM, and avoids alert spam when five people smell the same gas. |
| 24 | Merges re-run routing only when severity rises or a hazard is added. | A merge should never undo a dispatcher's manual priority change. |
| 25 | If the duplicate check's LLM call fails, the report becomes a new ticket. | A missed merge (extra ticket) is cheaper than hiding a separate problem. |
| 26 | Clustering uses HDBSCAN only when a building has ≥ 15 open tickets in the window; otherwise (or if HDBSCAN finds nothing) agglomerative clustering, average linkage, distance threshold 0.85 on [bge embedding, 0.6·floor/floors, 0.5·age/14 d]; clusters must have ≥ 3 tickets and mean pairwise cosine ≥ 0.60. | Measured on the seed: with 8 open tickets HDBSCAN labels everything noise at every setting (too few points for density); agglomerative at 0.85 recovers exactly the 5 planted water tickets and nothing else (0.9 starts merging unrelated tickets). |
| 27 | SOP retrieval ranks all chunks by cosine + 0.05 (same trade) + 0.08 (same asset type) instead of filtering by trade; the brief counts an SOP as "matched" only if similarity ≥ 0.62 with a trade/asset match or ≥ 0.70 without. | A ceiling drip (Plumbing) is best served by Ceiling Tile Replacement (General); a Wi-Fi or empty-soap ticket has no relevant SOP and the brief must say so instead of citing an unrelated one. |
| 28 | Dashboard KPI "duplicate reports merged (30 days)" counts all tickets (synthetic history included); latency and time-to-triage KPIs count only real pipeline reports. | Operational volume can come from demo data; performance numbers must be measured. |
| 29 | Trend chart folds trades beyond the top four into "Other" (neutral gray); colors follow the trade, slots validated with the dataviz palette validator in both modes; legend + table view always available. | ≤ 4 categorical slots stay CVD-safe on adjacent pairs; light-mode contrast warnings for aqua/yellow are relieved by the legend and table view. |
| 30 | Time-to-report measurements are recorded only in **study mode** (`/report?study=<label>`, linked from the legacy form) plus the legacy form itself. | Automated test runs were briefly counted as "SnapFix" timings (1 s, 143× faster) — fake numbers. Only deliberate volunteer runs count now. |
| 31 | The eval runs the real pipeline against an isolated, freshly seeded SQLite DB; unresolved locations are confirmed with the true room (simulating the reporter's pick); results JSON is committed so `/eval` has data on a fresh clone. | Never pollutes demo data; measures dedupe end to end; judges always see the latest run, clearly marked mock vs live. |
| 32 | The keyword mock was **not** tuned to the eval set's misses. Hazard rules were extended only for natural phrasings found while labelling, and each new phrase has a test (plus benign counter-examples like "the breaker keeps tripping"). | Tuning a classifier on its own test set inflates the numbers; safety rules are a deliberate, reviewed exception. |
| 33 | CLIP image similarity (Phase 5 stretch) was not added. | It adds a large model download and dependency for a marginal dedupe signal; text + location + category already gives F1 0.97 on the eval set. Listed as future work. |
